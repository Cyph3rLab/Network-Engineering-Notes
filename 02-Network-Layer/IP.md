# IP协议深度解析：从协议解剖到分片攻击与内网防御实战

> **实验环境**：Ubuntu 22.04 LTS / Kali Linux 2025.1 / Windows 11 22H2 / Wireshark 4.2.6 / Cisco IOS 15.2（模拟器）
>
> **合规声明**：本文所有攻击技术描述仅用于网络安全防护研究与授权环境下的安全测试。未经书面授权的网络攻击行为违反《中华人民共和国网络安全法》及《刑法》第285/286条，切勿用于非法目的。

## 一、核心概念与类比（IP的本质是什么？）

整个网络世界可类比为**邮政系统**：
- **MAC地址（二层）**：相当于**身份证号**，出厂即定，用于在同一栋楼（广播域）内精准识别住户。
- **IP地址（三层）**：相当于**邮寄地址**。这个地址是逻辑的、可变的，但它能跨城市（跨网络）将包裹送到你手上。

**IP协议的核心任务只有两个：**
1. **寻址**：给每一台接入网络的设备分配一个逻辑上的“门牌号”。
2. **分片与重组**：当数据包太大，超过出口链路的MTU时，IP负责将其切成小块发送，到达目的地后再拼装还原。

IP协议是**无连接**和**尽力而为**的——只管发，不保证不丢包、不保证按顺序到达。可靠性保障由上层协议（TCP）负责。

## 二、技术细节解剖：IPv4数据包的“基因序列”

IPv4头部长度通常为**20字节**（不含选项字段）。以Wireshark抓取的一个IPv4包为例（十六进制字节流）：
`45 00 00 3C 1A 2B 40 00 40 06 7C D1 C0 A8 01 0A C0 A8 01 14`

| 字段 | 长度 | 取值示例 | 工程师灵魂解析（攻防视角） |
|:---|:---:|:---|:---|
| **Version** | 4 bit | `4` | IPv4。防火墙可基于此直接丢弃非预期版本。 |
| **IHL** | 4 bit | `5` | 5 × 4字节 = 20字节（无选项）。现代安全设备通常直接丢弃带选项的包。 |
| **ToS** | 8 bit | `00` | 现为DSCP和ECN。攻击者可能伪造高优先级DSCP绕过限速。 |
| **Total Length** | 16 bit | `0x003C`=60 | IP包总长度。若超过MTU且DF=0则触发分片。 |
| **Identification** | 16 bit | `0x1A2B` | 同一数据包的所有分片共享此ID。现代OS采用随机化ID防Idle扫描。 |
| **Flags** | 3 bit | `010` | DF=1, MF=0。DF=1且超MTU时触发ICMP Type 3 Code 4。 |
| **Fragment Offset** | 13 bit | `0` | 以8字节为单位。泪滴攻击利用重叠偏移导致重组崩溃。 |
| **TTL** | 8 bit | `40`=64 | 每跳减1防环。通过初始值指纹识别OS（Linux 64，Windows 128）。 |
| **Protocol** | 8 bit | `0x06`=TCP | 标识载荷类型。防火墙ACL基于此匹配。 |
| **Header Checksum** | 16 bit | `0x7CD1` | 仅校验头部。因TTL每跳变，需重算。 |
| **Source IP** | 32 bit | `192.168.1.10` | IP欺骗核心目标。防御依赖uRPF。 |
| **Destination IP** | 32 bit | `192.168.1.20` | 路由器查表转发唯一依据。 |

## 三、分片与重组机制：IP最精妙也最危险的地方

### 3.1 为什么要分片？
以太网能传输的最大数据帧为1500字节（MTU）。若IP包总长度超过MTU且DF=0，IP层必须分片。若DF=1，路由器丢弃该包并返回ICMP Type 3 Code 4。

### 3.2 切分与重组逻辑（精确计算）
假设IP包总长度=3000字节，IP头20字节，则载荷为2980字节。以太网MTU=1500，单分片最大载荷为1480字节。需切成**三个分片**：

| 分片 | 总长度 | MF标志 | 偏移量(×8字节) | 载荷起始位置 |
|:---|:---:|:---:|:---:|:---|
| 分片1 | 1500字节 | 1 | 0 | 0 |
| 分片2 | 1500字节 | 1 | 185 (1480/8) | 1480字节处 |
| 分片3 | 40字节 | 0 | 370 (2960/8) | 2960字节处 |

接收端根据四元组（源IP，目的IP，协议号，ID）唯一确定原始包，按偏移量排序拼装后交付上层。

### 3.3 攻防演进
- **重叠分片攻击**：第二分片偏移量小于前一分片尾部，导致老旧系统整数溢出（CVE-1999-0015）。现代OS已修复，但工控OT设备仍有风险。
- **极小分片攻击**：首分片仅含IP头，不含四层端口，无状态防火墙因无法判断端口而放行。
- **现代防御**：现代状态防火墙默认启用**虚拟重组**，缓存所有分片拼装完整后再检测，超时（30-60秒）则丢弃。

## 四、IP转发与路由决策
三层设备收到IP包后执行：
1. 检查TTL，若≤0丢弃并返回ICMP Type 11。
2. 校验和检查。
3. **最长前缀匹配（LPM）**：查找路由表中匹配长度最长的条目。
4. TTL减1，重算校验和，转发。

## 五、内网攻防视角下的IP（红蓝对抗）

### 5.1 攻击者视角（红队）
- **IP欺骗**：伪造源IP发起DDoS反射攻击或绕过基于IP的信任认证。
- **TTL指纹识别**：通过回应包的TTL初始值推算OS。

### 5.2 防守者视角（蓝队）
1. **防IP欺骗——uRPF**：检查入向包的源IP路由出接口是否与接收接口一致。Cisco：`ip verify unicast source reachable-via rx`；Linux：`net.ipv4.conf.all.rp_filter = 1`。
2. **分片重组检查**：防火墙配置强制重组，设置重组超时和内存上限防耗尽。
3. **IP选项丢弃**：边界路由器直接丢弃带Source Route等选项的包（`ip options drop`）。

## 六、避坑指南与进阶延伸

### 坑1：认为“Ping不通”就是“IP不通”
服务器可能禁Ping（丢弃ICMP），但TCP 80/443开放。可靠测法：`nmap -sn -PS80,443 <target>`。

### 坑2：NAT破坏了端到端透明性
NAT修改IP头和端口，导致IPsec ESP流量无法穿越，必须启用NAT-T（UDP 4500封装）。

### 坑3：PMTUD黑洞
若DF=1且超MTU，路由器返回的ICMP Type 3 Code 4被防火墙拦截，导致TCP连接卡死。现代TCP协议栈通过PLPMTUD（RFC 8899）主动探测包大小来缓解此问题。

## 七、IPv6头部简要对比

| 特性 | IPv4 | IPv6（RFC 8200） |
|:---|:---|:---|
| 头部长度 | 20–60字节（可变） | 40字节（固定） |
| 分片机制 | 内置在基础头部中 | 移至扩展头 |
| 校验和 | 有（仅头部） | 无（依赖链路层和传输层） |
| IPsec支持 | 可选 | 原生支持（架构利于IPsec，但非强制组件） |

## 八、IP协议安全基线检查清单

| 检查项 | 基线标准 | 验证方法 |
|:---|:---|:---|
| uRPF（防IP欺骗） | 严格模式开启 | `sysctl net.ipv4.conf.all.rp_filter` |
| IP选项丢弃 | 边界丢弃带选项的包 | Cisco: `show running-config \| include ip options` |
| 分片重组启用 | 防火墙强制重组 | 检查防火墙虚拟重组配置 |
| TTL初始值 | 不泄露OS信息 | `net.ipv4.ip_default_ttl=255` |

## 九、IP分片攻击检测规则配置

> ⚠️ **风险提示**：以下规则需在测试环境验证兼容性后再部署，不同IDS引擎版本语法可能存在差异。

现代IDS（如Suricata）默认在底层通过 `defrag` 模块进行虚拟重组后，再将完整数据包交由规则引擎检测。以下为Snort/Suricata兼容的检测异常首分片规则示例：

```yaml
# 检测极小首分片攻击（载荷过小，无法包含完整的TCP/UDP端口字段）
alert ip any any -> any any (
  msg:"SUSPICIOUS TINY FIRST FRAGMENT - Potential evasion attempt";
  fragbits:M;        # 匹配More Fragments标志位为1的分片
  frag_offset:0;      # 确保是首分片
  dsize:<20;          # IP载荷小于20字节（不足以包含TCP 20字节头或UDP 8字节头）
  sid:2100001;
  rev:1;
)
```
*注：现代系统对Teardrop重叠分片的防护已由操作系统内核接管，无需在IDS层重复配置重叠检测规则。*

---

**总结**：IP协议是网络层的中枢，其无连接、尽力而为的设计使得上层协议必须自行保障可靠性。从攻防视角看，IP分片机制、TTL指纹、源地址伪造是攻击者的核心工具；uRPF、强制分片重组、IP选项丢弃是防御者的关键手段。掌握本文内容后，建议读者将IP知识与ICMP、ARP、路由协议串联，构建完整的网络层攻防知识体系。
