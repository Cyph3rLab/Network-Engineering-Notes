### 第一层：核心概念与本质（用分拣中心理解）

**路由（Routing）** 是指：网络设备（路由器或三层交换机）根据**路由表（Routing Table）** 中的条目，为每一个IP数据包**选择最佳出接口（或下一跳IP）** 的过程。

我们把全球互联网比作**联邦快递的全球分拣中心**：

-   **数据包** = 需要寄送的包裹。
-   **IP地址（如 8.8.8.8）** = 收件人的最终地址（国家、城市、街道）。
-   **路由表** = 贴在分拣员桌子上的“发件指南”。
    -   如果看到地址是“北京” → 扔进“北京专线”传送带（下一跳）。
    -   如果看到地址是“上海” → 扔进“上海专线”传送带。
    -   如果看到地址是“火星” → 扔进“默认传送带（Default Gateway）”给上级总站处理（默认路由）。

> **关键辨析（工程师必清）**：
> -   **路由（Routing）**：是**控制平面（Control Plane）** 的逻辑——决定“往哪走”（大脑思考）。
> -   **转发（Switching/Forwarding）**：是**数据平面（Data Plane）** 的动作——把包从某个接口扔出去（手部动作）。
> 一台路由器可以运行复杂的BGP路由协议（大脑很累），但如果硬件转发芯片（ASIC）坏了，手部动作停了，网络依然瘫痪。攻防中，攻击者优先攻击控制平面（如伪造OSPF Hello包让CPU满载）。


### 第二层：技术原理解剖（路由表的原子结构与匹配算法）

#### 1. 路由表的“基因序列”（一条完整路由长什么样？）
在Cisco设备中输入`show ip route`，或在Linux中输入`ip route show`，你看到的每一行路由条目，都包含以下最核心的四个要素：

| 字段 | 含义 | 示例值 | 攻防意义 |
| :--- | :--- | :--- | :--- |
| **目标网络/掩码** | 目的地址范围 | `10.0.20.0/24` | 匹配目标IP。**掩码越长，优先级越高**（这是漏洞利用的底层逻辑）。 |
| **管理距离（AD）** | 协议的**可信度**（数值越小越可信） | **直连=0**，**静态=1**，**OSPF=110**，**RIP=120** | 攻击者如果注入一个AD=1的伪造静态路由，可以覆盖掉你合法的AD=110的OSPF路由。 |
| **度量值（Metric）** | 到达目标的**距离/代价**（数值越小越优） | OSPF基于**带宽**（COST=10），RIP基于**跳数**（Hops=3） | 攻击者可以增大合法路由的Metric，让流量走备用（被控制的）链路。 |
| **下一跳（Next-Hop）** | 要把包发给**哪个相邻IP** | `192.168.1.1` | 这就是你真正的“出口”。如果下一跳被ARP欺骗，数据就丢了。 |

#### 2. 匹配算法（要命的最长前缀匹配，LPM）
当一个数据包（目标IP为 `10.0.20.5`）进入路由器时，它不挑“最宽的”，而是挑**“最精确的（掩码最长的）”**。

-   **路由表有**：
    -   路由A：`10.0.0.0/8`（匹配范围 10.0.0.0 ~ 10.255.255.255）
    -   路由B：`10.0.20.0/24`（匹配范围 10.0.20.0 ~ 10.0.20.255）
-   **匹配过程**：路由器将目标IP `10.0.20.5` 与所有路由条目做“按位与”运算，**两条都匹配**。但路由器选择**掩码更长的/24（即精确度更高）**。

> **安全陷阱（红队必看）**：如果攻击者向内网注入一条 `10.0.20.0/32`（主机路由），那么所有去往 `10.0.20.5` 的流量都会强行送到攻击者指定的下一跳，从而实现**精细化中间人攻击**，而不影响其他正常业务（极其隐蔽）。


### 第三层：路由协议的攻防地图（动态路由的信任危机）

路由分为**静态路由（手动写死）** 和**动态路由（协议自动学习）**。内网渗透中，攻击者最爱的就是动态路由协议，因为**它们默认信任网络中的邻居，且极少加密**。

#### 1. 静态路由（Static）—— 最安全，但运维麻烦
-   **特点**：管理员手动敲命令，`ip route 10.0.20.0 255.255.255.0 192.168.1.1`。
-   **攻击**：太难攻击了（除非你能登录设备改配置）。
-   **盲区**：如果内网配了**浮动静态路由（Floating Static）**作为备份，且AD值设得很高（如200）。攻击者无法覆盖它，因为主链路断了它才会生效。

#### 2. OSPF（开放式最短路径优先）—— 内网最常见的“活靶子”
OSPF工作在三层，通过组播 `224.0.0.5` 和 `224.0.0.6` 发送Hello包建立邻居关系。

-   **攻击手法（OSPF 邻居欺骗）**：
    1.  攻击者拿下内网一台服务器，开启IP转发。
    2.  使用工具（如 `Loki` 或 `Scapy`）伪造OSPF Hello报文，**宣称自己是“骨干区域（Area 0）”中的一台可信路由器**。
    3.  **致命点**：OSPF默认不加密（若未启用MD5认证）。合法路由器会“开心地”与攻击者建立Full（完全邻接）关系。
    4.  **利用**：攻击者向合法路由器发布`LSA（链路状态通告）`，宣称自己连接了某个关键网段（如`10.0.30.0/24`）且Metric为1。
    5.  **效果**：所有去往数据库网段（`10.0.30.0/24`）的流量被引向攻击机。攻击者开启转发，**几乎无感的中间人劫持**。
-   **防御**：在接口下必须配置 `ip ospf authentication message-digest` 和 `ip ospf message-digest-key 1 md5 [密码]`。**如果你在企业网里看到没用认证的OSPF，这等于给攻击者修了一条通往核心的“高速公路”。**

#### 3. BGP（边界网关协议）—— 互联网的“命脉”与“劫持重灾区”
（这是外网路由，但你必须懂原理，因为涉及DDoS防御）

-   **BGP劫持（前缀劫持）**：2008年，巴基斯坦电信误（或有意）宣告了YouTube的IP前缀（`208.65.153.0/24`），导致全球大部分YouTube流量被路由到巴基斯坦，业务中断数小时。
-   **红队视角（企业出口）**：虽然你在内网不太可能碰BGP，但如果你是企业边界工程师，攻击者没法直接攻破防火墙，但他可以**在互联网骨干层发一封恶意邮件给你的ISP，社会工程学诱导ISP修改BGP路由宣告**，把访问你公司网站的流量引到攻击者的仿冒服务器上（这种攻击不需要黑掉你的防火墙！）。


### 第四层：高级排障与红队实战场景（路由表的利用与破坏）

#### 场景1：利用“ICMP重定向”绕过网关（红队经典）
你之前学过ICMP Type 5（重定向）。攻击者在内网发送伪造的ICMP重定向包，告诉受害者PC：“去往 `8.8.8.8` 不要走网关（`192.168.1.1`）了，**走我这（攻击机`192.168.1.100`）更快**。”
-   **后果**：如果受害者主机**未禁用ICMP重定向**（Windows默认允许），其路由表会插入一条临时的**主机路由**（`8.8.8.8/32 via 192.168.1.100`）。流量立刻被劫持。
-   **防御**：在任何终端或服务器上，必须 `netsh interface ipv4 set global icmpredirects=disabled` 或修改Linux `net.ipv4.conf.all.accept_redirects = 0`。

#### 场景2：针对“策略路由（PBR）”的盲区
普通路由看“目的IP”，策略路由（Policy-Based Routing）看“源IP + 应用类型”。

-   **攻击利用**：假设企业规定“办公网段（`10.0.10.0/24`）”上网走出口A，“服务器网段（`10.0.20.0/24`）”走出口B。
-   攻击者在办公网拿下一台PC后，想访问外网C2，但他希望**伪装成服务器的流量特征**（避免被办公网的审计设备记录）。
-   他伪造数据包的源IP为 `10.0.20.10`（服务器IP），发往外网。交换机根据策略路由，直接将包扔到出口B，绕过了办公网的流量审计设备！**因此，在交换机上必须配置“uRPF（单播反向路径检查）”或“IP Source Guard”来拒绝这种伪造源IP的流量。**


### 第五层：避坑指南（资深网工的排障血泪史）

#### 坑1：认为“Ping通了网关就代表路由通”
-   **真相**：网关通了（直连），不代表能去其他网段。必须查**默认网关（0.0.0.0/0）**。如果你在终端执行 `route print` 发现没有 `0.0.0.0` 的下一跳，那所有非本网段的包都会丢掉。

#### 坑2：忽略“黑洞路由（Null0）”导致环路
-   管理员经常配置 `ip route 10.0.0.0/8 Null0` 来防环（将不存在的内部地址丢掉）。如果攻击者构造了一个目标IP为 `10.255.255.255` 的包，且没有这条黑洞路由，数据包可能会在路由器之间**弹来弹去（路由环路）**，最终TTL耗尽丢弃。

#### 坑3：递归路由查询（Recursive Lookup）造成的性能瓶颈
路由表中的下一跳（Next-Hop）不一定是你直连的邻居，可能是一个“间接地址”。路由器会查两次表。
-   比如：去往 `10.0.20.0/24` 的下一跳是 `192.168.2.2`。路由器必须再查一次 “去往 `192.168.2.2` 走哪个接口”。
-   如果递归条目出了问题（比如第二跳路由表被清空），即使第一条路由在，包也出不去。


### 第六层：总结与学习路线衔接

**路由是连接你所学所有知识的“总纲”**：

1.  **IP协议**：给你数据包填目标地址。
2.  **ARP**：帮你找到直连下一跳的MAC地址（三层决定走哪，二层负责敲门）。
3.  **VLAN**：划分广播域，但三层路由（SVI）是连接不同VLAN的桥梁。
4.  **NAT**：修改路由决策中的源/目标IP。

掌握了路由，你就掌握了攻击者在**网络层做中间人**的核心技能——**只要你能控制路由路径，你就能劫持一切未加密的流量。**
