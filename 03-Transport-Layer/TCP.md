# 一、TCP 是什么？

TCP（Transmission Control Protocol，传输控制协议）是一个**面向连接、可靠传输、基于字节流的协议**。

它位于：

```
应用层
   ↓
传输层
   ↓
TCP / UDP
   ↓
网络层 IP
   ↓
数据链路层
```

例如：

你访问：

```
https://example.com
```

实际上：

```
HTTP
 ↓
TLS
 ↓
TCP
 ↓
IP
 ↓
Ethernet/WiFi
```

TCP 负责：

-   建立连接
-   保证数据可靠到达
-   控制发送速度
-   按顺序重组数据

```

+---------------------+
| Source Port          |
+---------------------+
| Destination Port     |
+---------------------+
| Sequence Number      |
+---------------------+
| Acknowledgment Num   |
+---------------------+
| Data Offset | Flags  |
+---------------------+
| Window Size          |
+---------------------+
| Checksum             |
+---------------------+
| Urgent Pointer       |
+---------------------+
| Options              |
+---------------------+
```

重点字段：

## 1\. Source Port (源端口) / Destination Port (目的端口)

端口：

例如：

客户端：

```
192.168.1.10:52000
```

访问：

```
192.168.1.20:445
```

表示：

```
源端口:
52000

目标端口:
445(SMB)
```

例如：

```

```

# 三、TCP 三次握手（必须理解）

建立连接：

客户端：

```
Client                 Server

            SYN
       ---------------->

           SYN+ACK
       <----------------

            ACK
       ---------------->

           连接建立
```

详细：

## 第一次

客户端：

```
SYN=1

seq=x
```

意思：

> 我要建立连接，我的初始序列号是 x

---

## 第二次

服务器：

```
SYN=1
ACK=1

seq=y
ack=x+1
```

意思：

> 收到了你的请求，我的序列号是 y

---

## 第三次

客户端：

```
ACK=1

seq=x+1
ack=y+1
```

意思：

> 收到了你的序列号

连接建立。

---

# 四、为什么需要三次握手？

核心原因：

## 1\. 确认双方收发能力

假设：

客户端：

```
我能发
```

服务器：

```
我能收
我能发
```

客户端：

```
我能收
```

双方确认：

```
发送能力 √
接收能力 √
```

---

## 2\. 防止历史连接影响

例如：

旧 SYN：

```
SYN seq=100
```

因为网络延迟：

10秒后才到服务器。

如果没有三次确认：

服务器可能认为：

```
新的连接
```

实际上：

这是旧数据。

---

# 五、TCP 四次挥手

关闭连接：

```
Client              Server


            FIN
       ---------------->


            ACK
       <----------------


            FIN
       <----------------


            ACK
       ---------------->


关闭
```

为什么需要四次？

因为 TCP 是：

```
双向通信
```

双方关闭方向独立。

例如：

客户端：

```
我不发送了
```

但是服务器：

```
我还有数据发送
```

所以不能直接断。

---

# 六、TCP 如何保证可靠？

这是重点。

## 1\. 序列号 Sequence Number

TCP 数据：

不是：

```
数据1
数据2
数据3
```

而是：

```
seq 1000
hello

seq 1005
world
```

如果：

```
1000
1005
1010
```

乱序：

TCP 可以重新排序。

---

## 2\. ACK确认机制

服务器收到：

```
seq=1000
长度100
```

回复：

```
ACK=1100
```

意思：

> 我已经收到1000-1099

---

## 3\. 超时重传

如果：

```
发送:

seq=1000


没有ACK
```

TCP：

重新发送。

---

# 七、TCP 流量控制

问题：

发送方太快怎么办？

例如：

客户端：

```
100MB/s
```

服务器：

```
10MB/s
```

服务器告诉客户端：

```
Window Size=10KB
```

意思：

> 你最多发10KB

这叫：

```
滑动窗口
```

---

# 八、TCP 拥塞控制

和流量控制不同。

流量控制：

```
保护接收方
```

拥塞控制：

```
保护网络
```

例如：

网络堵塞：

TCP降低速度：

```
100M
 ↓
50M
 ↓
10M
```

算法：

-   慢启动
-   拥塞避免
-   快速重传
-   快速恢复

# 九、TCP 和安全的关系（重点）

作为红队，你需要关注这些：

---

## 1\. SYN Flood

攻击：

大量发送：

```
SYN
```

但是：

不完成第三次握手。

服务器：

```
SYN_RECV
SYN_RECV
SYN_RECV
```

资源耗尽。

防御：

-   SYN Cookie
-   防火墙限制

---

## 2\. TCP Reset 攻击

发送：

```
RST
```

强制关闭连接。

可能导致：

-   会话中断
-   BGP攻击

---

## 3\. TCP 会话劫持

攻击者：

预测：

```
seq
ack
```

伪造：

```
ACK
```

现代 TCP：

随机序列号降低风险。

---

## 4\. TCP 端口扫描

你以后学 nmap：

本质就是 TCP。

例如：

SYN扫描：

```
攻击者

SYN
----->

开放端口:

SYN ACK
<-----

关闭:

RST
<-----
```

nmap：

```
-sS
```

就是：

TCP SYN Scan。
