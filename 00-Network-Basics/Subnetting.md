# 子网划分与企业内网应用实战

> **文档定位**：本文档面向网络工程与内网安全方向,旨在打通从基础子网计算到企业级访问控制与攻击路径理解的完整链条。核心观点不仅包含原理,更强调了 **"子网划分是安全策略的物理基础"** 这一实战理念。

## 1. 核心定义与本质

### 1.1 什么是子网划分？
**子网划分** 是将一个单一的IP网络逻辑上切分为多个更小的网络。它并非简单的数字游戏,而是为了在广播域、安全性和路由管理上实现更精细的控制。

### 1.2 技术本质：修改网络前缀长度
子网划分的本质是从IP地址的**主机位**借位作为新的**网络位**。

- **IPv4地址结构**：`网络部分 | 主机部分`
- **关键操作**：通过延长子网掩码(如从 `/24` 变为 `/26`),将原本的一个大广播域拆分为多个逻辑网络。

**示例**：
`192.168.1.0/24` 变为 `192.168.1.0/26`：

- 借用了 **2** 个主机位 → 产生 `2^2 = 4` 个子网。
- 每个子网剩余 **6** 个主机位 → 每个子网有 `2^6 - 2 = 62` 个可用地址。

> **关键修正**：现代企业网(使用RFC 1918私有地址)进行子网划分,首要目的已非"节省IP地址",而是**便于路由聚合、实现安全隔离和简化运维**。

## 2. 核心概念辨析(避坑指南)

在企业环境中,有几个概念极易混淆,这里是基于实战的严谨界定：

### 2.1 子网 vs VLAN
- **子网**：**三层逻辑概念**。用于判断IP包该由二层转发(同网段)还是三层路由(跨网段)。
- **VLAN**：**二层隔离概念**。用于划分广播域,通过Tag(802.1Q)隔离流量。
- **关系**：**企业标准实践中,通常将一个VLAN绑定一个子网**。但严格来说,二者并非强制一对一绑定,错误的绑定会导致ARP混乱或路由黑洞。

### 2.2 广播域 vs 冲突域 vs 子网
- **冲突域**：已由交换机(Switch)解决,每个端口为一个冲突域。
- **广播域**：由VLAN划分,一个VLAN就是一个广播域。
- **子网**：三层逻辑网络,跨子网通信必须经由三层设备(网关/路由器)。

## 3. 子网掩码的运算逻辑

子网掩码用于判断两台主机是否在同一网段。

**判定方法**：IP地址与子网掩码进行 **AND(与)运算**。若运算结果(网络号)相同,则在同一网段。

### 3.1 同网段示例
- A: `192.168.1.10/24` → 网络号 `192.168.1.0`
- B: `192.168.1.200/24` → 网络号 `192.168.1.0`
- **结论**：同网段,直接ARP寻址通信。

### 3.2 跨网段示例
- A: `192.168.1.10/24` → 网络号 `192.168.1.0`
- B: `192.168.2.10/24` → 网络号 `192.168.2.0`
- **结论**：不同网段,需将数据包发往**默认网关**,由网关进行路由转发。

## 4. 企业级地址规划方案

放弃混乱的 `192.168.1.0/24` 平铺,采用基于RFC 1918的层次化地址规划：

| 业务区域 | IP网段 | 子网掩码 | 说明 |
| :--- | :--- | :--- | :--- |
| **总部核心** | `10.0.0.0/16` | `255.255.0.0` | 总部内网汇总路由 |
| **办公网段** | `10.0.10.0/24` | `255.255.255.0` | 员工有线/无线终端 |
| **服务器区** | `10.0.20.0/24` | `255.255.255.0` | 对外业务应用服务器 |
| **数据库区** | `10.0.30.0/24` | `255.255.255.0` | 核心数据存储 |
| **安全管理区** | `10.0.100.0/24` | `255.255.255.0` | 堡垒机、域控、网管平台 |

**优势**：

- **路由聚合**：核心路由器只需宣告 `10.0.0.0/16`,而非成百上千条明细路由。
- **快速定位**：通过IP段即可迅速判断资产归属类型。

## 5. 攻防视角下的子网与ACL

子网划分如果不配合访问控制列表(ACL)或防火墙策略,则**不直接等同于安全**。

### 5.1 攻击者视角(横向移动)
当攻击者通过钓鱼或漏洞进入办公网(`10.0.10.0/24`)后：

1. **信息收集**：执行 `ipconfig` 查看本机IP,确认网关(三层交换机)。
2. **存活探测**：使用 `nmap -sn 10.0.0.0/16`,快速寻找响应ICMP或TCP端口的存活主机。
3. **跨网段扫描**：发现服务器区 `10.0.20.0/24` 和数据库区 `10.0.30.0/24` 的开放端口(如445 SMB, 1433 MSSQL)。

> **如果ACL配置过于宽松(如允许办公网访问任意目标)** ,攻击者将直接跨网段攻击数据库。

### 5.2 防守者视角(策略控制)
**目标**：将"子网划分"转化为"微隔离策略"。

- **允许策略**：办公网 → 仅允许访问 DNS、OA 系统、HTTP代理。
- **严格禁止**：办公网 → 禁止访问数据库网段(`10.0.30.0/24`)及域控管理端口(如TCP 445, 5986)。
- **检测手段**：部署IDS/NDR,重点检测 **"异常跨网段扫描"** (如短时间内大量ICMP探测或TCP SYN扫描)。

## 6. 三层边界部署细节(实操建议)

在企业交换机或防火墙上配置ACL时,需注意以下陷阱：

1. **隐含规则**：大多数设备ACL末尾默认 `deny any any`。但如果配置了 `permit ip any any`,则子网划分将丧失任何安全意义。
2. **控制面流量**：需确保OSPF、VRRP/HSRP等路由协议的心跳报文(通常为组播/广播)不被误拦截,否则导致路由震荡或设备主备切换异常。
3. **网关地址规划**：
   - 通常习惯使用子网的第一个可用地址作为网关(如 `10.0.10.1`)。
   - **错误规划网关会导致跨网段通信失效**。

## 7. 学习路径与进阶建议

如果你在内网安全和网络工程方向深耕,建议按以下技术链条逐步深入：

> **CIDR计算** → **VLAN原理与Trunk** → **三层交换(SVI)与VLAN间路由** → **ACL与防火墙策略** → **攻击路径与横向移动绕过**

当你熟练掌握了子网和VLAN的联动后,可以尝试思考以下实战场景(后续研究课题)：

- 如果防火墙只允许服务器区访问数据库,攻击者在办公网跳板机上,如何利用**双宿主主机**(同时连通两个网段的服务器)进行**跳板攻击**？
- 如何基于子网规划实现**业务系统的逻辑微分段**,防止勒索病毒在内网大面积感染？
