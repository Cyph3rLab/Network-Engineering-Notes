## 第一层：协议解剖——BPDU报文的“基因序列”

STP协议的所有秘密都写在BPDU（Bridge Protocol Data Unit）里。它不封装在IP包里，而是**直接封装在以太网帧中**，目的MAC地址是著名的组播地址：`01:80:C2:00:00:00`。

**完整的BPDU帧结构（IEEE 802.1D 标准）**

```text
[ 以太网首部 (14字节) ]
  目的MAC: 01:80:C2:00:00:00 (STP组播)
  源MAC:   交换机自身接口MAC
  类型:    0x0026 (LLDP) 或 0x0000 (取决于封装)

[ LLC头部 (3字节) ]
  DSAP: 0x42
  SSAP: 0x42
  Ctrl: 0x03

[ BPDU载荷 (35字节 - 核心区) ]
  协议ID: 0x0000 (固定，代表STP)
  版本:   0x00 (STP) 或 0x02 (RSTP)
  BPDU类型: 0x00 (配置BPDU) 或 0x80 (TCN拓扑变更通知)
  标志位:  1字节 (RSTP中用于提议/同意)
  根桥ID:  8字节 (优先级2字节 + MAC地址6字节)
  根路径开销: 4字节 (Cisco默认使用短格式，标准为长格式)
  发送者桥ID: 8字节
  发送者端口ID: 2字节 (优先级1字节 + 端口号1字节)
  消息寿命: 2字节 (当前BPDU的跳数，从根桥发出为0)
  最大寿命: 2字节 (默认20秒，即老化超时时间)
  Hello时间: 2字节 (默认2秒，根桥发送周期)
  转发延迟: 2字节 (默认15秒，Listening和Learning状态持续时间)
```

> **攻击者发现**：这35个字节里，**标志位**、**根桥ID**（尤其是优先级）、**根路径开销** 是攻击者最核心的篡改目标。

## 第二层：选举算法的“原子级”拆解

STP的选举不是“商量”，而是一场严格按照“**大小比较器**”逻辑运行的数学竞赛。

### 根桥选举：四步走

1.  **初始状态**：每个交换机启动时，都认为自己是根桥，将“根桥ID”字段填成自己的桥ID。
2.  **发送BPDU**：所有交换机通过所有端口周期性（Hello时间）发送BPDU。
3.  **比较**：交换机收到BPDU后，提取其中的“根桥ID”，与本机保存的“最优根桥ID”进行比较。
4.  **更新与传播**：如果收到的根桥ID更小（优先级更小，或优先级相同MAC更小），则更新自己的根桥ID，并停止发送自己的BPDU，开始转发这个更优的BPDU。

**场景复现（两交换机）**：

-   SW1: 优先级 `32768`，MAC `00:00:00:00:00:0A`
-   SW2: 优先级 `32768`，MAC `00:00:00:00:00:0B`

初始时，SW1 发送 BPDU（根桥=SW1），SW2 发送 BPDU（根桥=SW2）。双方收到对方报文后，经过比较，发现 `0A < 0B`，于是 SW1 胜出，SW2 将“根桥ID”更新为 SW1，并停止发送自己的BPDU，转而中继 SW1 的 BPDU。

### 端口角色选举：决定性因子

当端口收到BPDU时，交换机运行以下**严格优先序**的比较逻辑：

1.  **最低根桥ID**：谁的“根桥ID”小，谁离根更近。
2.  **最低根路径开销**：如果根桥相同，计算从端口到达根桥的累积开销，数值越小越优。
3.  **最低发送者桥ID**：如果开销相同，比较对端交换机的桥ID。
4.  **最低发送者端口ID**：如果对端交换机也相同，比较对端发送BPDU的端口ID。

**路径开销的精确计算公式（IEEE 802.1D-2004 标准）**：

-   `路径开销 = 2,000,000,000 / 链路带宽 (bps)`
-   10 Mbps = 200,000,000 / 10,000,000 = **100**
-   100 Mbps = 200,000,000 / 100,000,000 = **19**
-   1 Gbps = 200,000,000 / 1,000,000,000 = **4**
-   10 Gbps = 200,000,000 / 10,000,000,000 = **2**

## 第三层：精确的收敛时间计算（数学建模）

传统STP的收敛时间是它最大的性能短板。我们现在来计算一个极端情况：**根桥宕机**。

**收敛时间公式**：
`收敛时间 = Max Age (老化时间) + 2 × Forward Delay (转发延迟)`

-   **Max Age = 20秒**：交换机需要等待20秒，确认没有收到来自根桥的BPDU，才认为根桥失效。
-   **Forward Delay = 15秒**：在拓扑变更后，为防临时环路，端口必须经过 `Listening` (15秒) 和 `Learning` (15秒) 状态，才进入 `Forwarding`。

**总计：20 + 15 + 15 = 50秒**。

> **实验验证**：在真实网络中，如果核心交换机电源故障，接入层设备需要整整50秒才能将备用链路切换到转发状态。这50秒在关键业务（如股票交易、工业控制）中是灾难性的。这正是RSTP出现的原因。

## 第四层：攻防实战的“手术刀级”细节

### 1. 攻击工具工作原理（以 `yersinia` 为例）

当你运行 `yersinia -I` 进入STP攻击菜单时，底层发生了什么？

-   **伪造BPDU**：`yersinia` 会构造一个以太网帧，目的MAC为 `01:80:C2:00:00:00`，在BPDU头部将“根桥ID”的优先级设置为 `0`（最小可能值），MAC地址设置为攻击机MAC（或任意虚构MAC）。
-   **持续投毒**：它会以极高的频率（远快于2秒的Hello时间）发送这个伪造报文。
-   **抢占根桥**：因为优先级 `0` 小于任何合法交换机的 `32768`，全网交换机将被迫将攻击机选为新的根桥。
-   **中间人攻击**：一旦成为根桥，所有交换机的**根端口**都将指向攻击者所在的链路，所有跨交换机的流量都将经过攻击机，实现MITM。

### 2. 攻击变形：TCN（拓扑变更）泛洪攻击

这是更隐蔽的DoS攻击。`yersinia` 或 `scapy` 可以伪造 **TCN BPDU (类型0x80)**，持续向交换机发送。

-   **后果**：交换机收到TCN后，会立即向根桥发送TCN，根桥收到后会泛洪 **TC (Topology Change)** 标志位，强制全网交换机将MAC地址表的老化时间从300秒降低到 **15秒（Forward Delay）**。
-   **破坏力**：MAC表被频繁清空，导致大量单播帧变为**未知单播泛洪**，网络性能急剧下降，相当于持续的人为MAC泛洪攻击。

### 3. 防御的底层逻辑

-   **BPDU Guard 的硬件级实现**：当交换机端口收到第一个BPDU时，ASIC芯片会触发一个中断，将端口状态直接设置为 `errdisable`。这不是软件慢速处理，而是**硬件直接切断**，响应时间在毫秒级。
-   **Root Guard 的工作机制**：在端口上启用 `spanning-tree guard root`，交换机会额外检查收到的BPDU中的“根桥ID”。如果发现这个ID比自己当前保存的根桥**更优**，它会将该端口置为 `root-inconsistent` 状态，**只接收不转发**BPDU，从而阻止攻击者通过该端口成为根桥。

## 第五层：进阶延伸——RSTP 与 MSTP 的深度差异

### RSTP (802.1w) 的“核武器”级改进

-   **边缘端口**：直接连接终端的端口，不参与STP计算，直接进入转发状态（0秒收敛）。**攻击面**：如果攻击者接入边缘端口并发送BPDU，仍可造成威胁，因此仍需配置 `BPDU Guard`。
-   **提议/同意机制**：通过 `Proposal` 和 `Agreement` 标志位，让交换机之间通过点对点握手协商，将端口直接从 `Discarding` 状态切换到 `Forwarding` 状态，无需等待30秒。收敛时间理论上 **< 1秒**。

### MSTP (802.1s) 的工程价值

-   **实例映射**：它允许你将一组VLAN映射到同一个STP实例。例如，实例1负责VLAN 10-20，实例2负责VLAN 21-30。
-   **负载均衡**：你可以在交换机A上设置实例1优先级为8192（根），实例2优先级为16384（备份）；在交换机B上设置相反。这样就实现了**不同VLAN的流量走不同路径**，实现链路负载均衡。

## 终极配置模板（Cisco 标准生产环境）

```cisco
! 全局配置
spanning-tree vlan 1-4094 priority 4096   ! 将此交换机设为根桥，优先级设为最小
spanning-tree vlan 1-4094 root primary    ! 或者使用这条自动命令

! 端口安全配置
interface GigabitEthernet0/1
 description CONNECT_TO_USER_PC
 spanning-tree portfast                 ! 立即进入转发状态（用于接入PC）
 spanning-tree bpduguard enable         ! 收到BPDU即关闭端口

interface GigabitEthernet0/24
 description UPLINK_TO_CORE
 spanning-tree guard root              ! 连接核心交换机的口，防止被下游交换机抢根
 spanning-tree link-type point-to-point ! 强制点对点，加速RSTP收敛
```
